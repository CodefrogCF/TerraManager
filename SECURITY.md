# TerraManager Security Policy

## Supported versions

Before v1.0, security fixes are provided on a best-effort basis for the latest
development or released version only. The supported-version policy may be
revised when v1.0 is published.

## Reporting a vulnerability

Use GitHub private vulnerability reporting for the TerraManager repository when
that feature is available. If no private reporting channel is visible, open a
minimal GitHub Issue asking the maintainer to establish private contact. Do not
include exploit instructions, private application data or credentials in that
public issue.

A private report should include the affected version, platform, reproduction
conditions, potential impact and any suggested mitigation. Never attach a real
`.tmbackup`, keystore, password, token, signing key or user picture.

Reports are reviewed on a best-effort basis. Receipt does not create a service-
level agreement, bounty commitment or guaranteed release schedule.
