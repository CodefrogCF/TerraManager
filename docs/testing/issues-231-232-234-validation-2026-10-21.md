# Issues #231, #232 and #234: implementation and validation

Date: 2026-10-21. Source baseline: `64b4d596f0cb76bb7f30e78a21aaa7fe6d9b8883`.

## Delivered behavior

### #231: Standalone overview menus

- Removed the dedicated Rename Animal and Rename Box actions from the
  Standalone overview context menus, including their unused page handlers.
- Names remain editable on the existing Edit Animal and Edit Box pages.
- Other menu actions and the Shared Care overview menus are unchanged.

### #232: pictures while creating Shared Care entities

- Create Animal and Create Box offer the existing picture selection controls,
  source selection, crop editor and picture optimizer, with a preview before
  saving. Selecting a picture is optional and performs no server write.
- A confirmed entity creation is followed by the existing gallery upload API.
  The first picture uses the existing primary-picture behavior. Existing
  mutation reconciliation and data invalidation refresh the overview data.
- A cancelled selection leaves the form usable. Selection/processing errors
  are shown in the form and do not create an entity.
- Save is disabled during picture processing and persistence.
- If creation succeeds but upload fails or its reply is lost, the form retains
  the confirmed entity and upload request ID. Retry sends only the same image
  request; it does not create another entity. The user can also finish and
  inspect the existing entity's gallery. No offline write queue is added.
- German and English labels use the application's existing localization
  mechanisms. There are no new packages, device permissions or server routes.
- Existing entity edit/gallery workflows and Standalone picture handling are
  unchanged.

### #234: expanded overdue feeding summary

- Both overview variants explicitly give the expanded and collapsed tile a
  transparent top/bottom border, preserving the default border insets.
- Existing item content, internal separators, padding and expand/collapse
  behavior are retained.

### Windows browser-test environment

The initial Chrome invocation could not start tests because the Flutter 3.47.2
test server returned 404 for its existing local CanvasKit files. In
`flutter_web_platform.dart`, `_localCanvasKitHandler` converted a URL to a
Windows filesystem path before testing the forward-slash URL prefix. Browser
diagnostics confirmed the failing URLs and the files were present in the SDK.

For validation only, the isolated SDK used `request.url.path` for that prefix
check. The original SDK source, tool snapshot and stamp were backed up and
restored after validation, with their hashes checked. This workaround is not an
application change and is not included in the ZIP. No SDK artifact download or application permission change was needed
to repair the CanvasKit routing.

The Windows web-test bootstrap also stripped the directory separator from the
nested test filename (`shared_clientshared_creation_picture_test.dart`). A
temporary root-level test entry imported the unchanged original test file and
called its `main()`, avoiding a directory separator in the generated test ID.
The adapter was validation-only and was removed before packaging. The browser
run still executes the same 20 test cases from the delivered test source.

## Manual acceptance boundary

Automated widget tests exercise source selection and uploads through fakes.
They do not certify a physical Android camera/gallery picker, a browser's file
chooser or an actual device's rendering. After deployment, verify on the target
Android device and Shared Care browser:

1. Create one Box and one Animal with a picture, and check preview, primary
   thumbnail, details and gallery after saving.
2. Cancel picture selection and create an entity without a picture.
3. Confirm Standalone overview menus omit Rename and editing still changes names.
4. Expand/collapse the overdue summary in light and dark themes.

The ZIP contains source changes and requires rebuilding the Shared Care Web
client and the Standalone application. Server source, schema, authentication,
role checks and the SSE implementation are unchanged.
